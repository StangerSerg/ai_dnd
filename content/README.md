# Встроенный контент

Данные, с которыми портал работает «из коробки». Всё встроенное — на русском и английском. Что и когда появляется — в [плане](../docs/PLAN.md), этап 1.

| Папка | Что внутри | Статус |
|---|---|---|
| `sheets/` | Шаблоны карточек персонажа | есть «5e SRD (базовый)» |
| `characters/ru/`, `characters/en/` | Готовые персонажи для демо-сценария | воин, плут и жрец 3-го уровня |
| `rulesets/` | Наборы правил | есть «5-я редакция (SRD 5.1)» |
| `bestiary/` | Библиотеки статблоков монстров | десять базовых существ SRD |
| `scenarios/` | Сценарии | демо «Тень над Мельничьим Бродом», ru и en |
| `glossary.yaml` | Глоссарий терминов ru/en | 54 общих термина |

## Сценарий

[scenarios/shadow-over-millford.ru.yaml](scenarios/shadow-over-millford.ru.yaml) и [английская версия](scenarios/shadow-over-millford.en.yaml) — демо на четыре сцены для трёх героев 3-го уровня. Формат описан в архитектуре, раздел 8.1; схема — в `backend/src/ai_dnd/scenarios/schemas.py`.

Сценарий — набор сущностей: сцены, NPC, предметы, улики, раздаточные материалы, столкновения, сведения о мире, карта. Сущности ссылаются друг на друга по id, и при загрузке все ссылки проверяются: переходы между сценами, NPC и улики в сценах, что открывает проверка, статблоки в столкновениях. Сцена, в которую нельзя попасть из стартовой, — тоже ошибка.

Версии на разных языках — отдельные файлы с одинаковыми id и числами: различаются только тексты.

## Монстры

[bestiary/srd.yaml](bestiary/srd.yaml) — статблоки существ. Из сценария на них ссылаются как `srd:goblin`; свои статблоки сценарий может описать в разделе `statblocks`. В статблоке лежат готовые бонусы проверок и спасбросков, класс доспеха, хиты, атаки и правила поведения в бою (`tactics`). Особенности, которые движок сам не считает (`traits`), остаются текстом для ведущего.

Числа записаны по памяти из SRD 5.1 и ждут сверки с первоисточником.

## Глоссарий

[glossary.yaml](glossary.yaml) — как термины называются на каждом языке, чтобы перевод был одним и тем же в интерфейсе и в ответах ИИ. Названия характеристик, навыков, состояний и типов урона в файл не входят: они берутся из набора правил.

## Набор правил

[rulesets/dnd5e-srd.json](rulesets/dnd5e-srd.json) — правила как данные (архитектура, раздел 6.1); схема — в `backend/src/ai_dnd/rules/ruleset.py`. В наборе записано:

- `resolution` — какие кости бросать на проверку и как читать результат. Здесь это «1d20 + бонус против сложности»; движок умеет и «кости + бонус, исход по диапазонам» (например, 2d6).
- `difficulty` — число для каждого уровня сложности: ИИ называет уровень словом, число берётся отсюда.
- `checks`, `saves` — проверки и спасброски. У навыка указана характеристика: если у участника нет своего бонуса для навыка, берётся её бонус.
- `damage_types`, `resources`, `conditions` — типы урона, правила восстановления ресурсов при отдыхе, состояния и их влияние на броски.
- `combat` — кости атаки, критические попадания, что происходит при 0 хитов.

Шаблон карточки ссылается на свой набор правил (`"ruleset": "dnd5e-srd@1"`); что они подходят друг к другу, проверяет тест.

## Шаблон карточки

[sheets/srd5-basic.json](sheets/srd5-basic.json) — шаблон «5e SRD (базовый)». Формат описан в [архитектуре](../docs/ARCHITECTURE.md), раздел 7.1; схема — в `backend/src/ai_dnd/sheets/schemas.py`.

В шаблоне три части:

- `fields` — поля карточки. Вычисляемые поля (`computed`) и максимумы ресурсов (`max_formula`) считаются формулами.
- `layout` — разделы карточки и порядок полей в них.
- `bindings` — как полями пользуется движок правил: бонусы проверок и спасбросков, хиты, класс доспеха, бонус инициативы, список атак.

## Готовые персонажи

Файл персонажа — ссылка на версию шаблона и значения полей:

```json
{
  "template": "srd5-basic@1",
  "values": {"name": "Бранд", "level": 3, "str": 16, "hp": {"current": 28}}
}
```

Хранится только то, что вводит игрок. Чего в файле нет, берётся из значений по умолчанию шаблона; вычисляемые поля хранить нельзя. Русская и английская версии одного персонажа различаются только текстами — это проверяет тест.

## Проверка

Весь контент проверяется тестами бэкенда: шаблон собирается без ошибок, все подписи есть на обоих языках, цифры готовых персонажей совпадают с посчитанными вручную.

```bash
cd backend && uv run pytest
```
